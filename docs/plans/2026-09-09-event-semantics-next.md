# 다음 이벤트 의미 검증·구현 계획

2026-09-09. 이번 머지는 기존 레코드 경계·native 카운터·시계 검증과 발견 문서의 기준점을 만든다. 아래 항목은 **후속 작업**이며 이번 머지의 완료 항목으로 계산하지 않는다.

근거: [사망 액션과 구조물 분류](../../vg/docs/DEATH_EVENTS_2026-09-09.md), [종료 경계](../../vg/docs/ENDGAME_BOUNDARY_2026-09-08.md), [이벤트 목록](../../vg/docs/EVENT_CATALOG_2026-09-08.md).

## 1. 사망 액션을 타임라인에 노출

- 대상: `vg/analysis/event_timeline.py`, 대응 테스트.
- `0x0430`을 native `ActionActorDie`로 명명한다. 해당 빌드와 관찰된 길이에 한정하고 피해 개체 ID·원시 사망 원인 ID·나머지 바이트를 보존한다.
- `041c` 카운터 업데이트와 `0431` 상태 전환은 별도 행으로 유지한다. 원시 source를 `credited_killer`로 이름 붙이지 않는다.
- 기본 opcode 목록·`--entity` 필터에서 피해자와 source가 일관되게 동작하도록 한다. 기록 시각과 게임 시각을 섞지 않는다.
- 검증: 정상 사망, source sentinel/비플레이어, 짧거나 긴 본문, 다른 이벤트의 유사 바이트, entity 필터, 여러 섹션, CLI help/정상/잘린 입력. 실제 직접 경기 `1500 ← 2007` 행을 확인한다.
- 완료 기준: lossless 타임라인이 사건을 식별하고 카운터 합계·완료 판정을 변경하지 않는다.

## 2. 개체 ID를 구체적인 종류에 연결

- 새로운 `vg/core` 모듈을 기존 `vgr_records`/타임라인 계층과 연결한다. 리플레이의 `03f2/03f3` 생성 상태와 검증된 정의 목록을 사용한다.
- 입력은 사용자가 보유한 정의 목록과 빌드 해시다. ID나 정의 번호를 전역 상수로 고정하지 않고 스폰·재스폰·ID 수명을 구분한다.
- 영웅/구조물/몬스터 등 큰 분류와 `VainCrystal_Away_5v5`, `Turret5v5`, `VainNode` 같은 구체적인 이름을 구별한다. 타입 미확정은 unknown으로 남긴다.
- Manifest 읽기를 제품화할 때는 길이·버전·인덱스·relocation 범위와 해시를 검사하고 원본을 덮어쓰지 않는다. 게임 바이너리/리소스를 재배포하지 않는다.
- 검증: 크리스탈, 타워, 베인 노드 각각의 생성 행; 잘못된 빌드/누락된 정의/범위 밖 인덱스; 같은 숫자 ID를 가진 다른 기록. 최소 두 종류의 화면 대조를 추가한다.
- 완료 기준: source 종류가 근거와 함께 나오며, 소유자/소환체와 킬 인정 영웅은 아직 별도 필드로 남는다.

## 3. 종료 직전 39개 사망 액션과 집계 차이 규명

- 대상: `native_stats`, `completeness`, 기존 EOF/캡처 검증 도구. 먼저 조사하며 acceptance를 먼저 바꾸지 않는다.
- 현재 관찰: layer-0 데스 ADD-1 2,182건은 사망 액션과 대응한다. 반대 방향에서는 종료 전 0.119~5.813초의 액션 39건이 해당 증가와 대응하지 않는다.
- 구분할 가설: (a) 다른 SET/스냅샷/레이어에 반영, (b) 종료 과정에서 카운터 집계가 먼저 고정, (c) 액션 큐/기록 시각과 UI 적용 순서 차이. 어느 하나를 미리 정답으로 채택하지 않는다.
- 기존 39건의 모든 관련 상태 연산과 최종 스냅샷을 재구성한다. 같은 시각 후속 레코드를 보존한다.
- 실제 비항복 종료를 하나 확보한다. 캡처는 사망·크리스탈 파괴·결과 화면까지 지속하고 시간 제한/남은 촬영 시간을 확인한다. 기존 16:01 캡처 중단을 반복하지 않는다.
- 화면/파일을 게임 시계로 대조하되 소수점 기록 시각을 정확한 화면 전환으로 단정하지 않는다. 타깃 리플레이 실행이 다시 실패하면 정해진 대조군으로 전환하고 별도 크래시 조사로 무제한 확대하지 않는다.
- 완료 기준: 검증된 종료 경계와 결과 KDA를 독립적으로 설명하는 사례가 있고, 39건의 차이에 대한 근거가 생긴다. 그 전까지 `사망 액션 수 = 최종 데스`는 금지한다.

## 4. 킬 귀속·어시스트·경제 이벤트

- 원시 source → 소유자/대체 actor → 킬 인정 플레이어 경로를 확인한다. 플레이어/타워/크리스탈/소환체 사망을 나눠 검증한다.
- 어시스트는 참여자 집합과 카운터 ADD를 구별한다. 같은 시각이라는 이유로 모든 참조를 참여자로 넣지 않는다.
- 경제는 대기 → 구매 → 판매 → 단독 처치 → 공유 보상 순서로 소지금·누적 수입·지출을 분리한다. 레벨·XP·스킬 강화도 각각 분리한다.
- 완료 기준: 단일 행동을 파일 변화와 화면 수치로 재현하고 경계/음성 사례까지 확인한 항목만 라벨을 붙인다.

## 5. 목표물·전투 효과·좌표 확장

- 구조물/대형 몬스터 분류를 바탕으로 파괴·포획·재등장·팀 보상을 구별한다.
- 좌표는 월드 위치·목적지·효과 위치를 분리하고 정지/직선/돌진을 대조한다.
- 스킬은 두 캐릭터의 단일 A/B/C부터 시전/취소/적중/버프 해제를 구별한다. 범용 라벨로 빠르게 확대하지 않는다.
