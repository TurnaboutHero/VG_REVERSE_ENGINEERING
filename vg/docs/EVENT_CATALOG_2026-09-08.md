# 이벤트 해석·검증 현황

2026-09-08 조사, 한국 시간 9월 9일까지 이어진 검증. 현재 코드와 날짜가 있는 분석 근거를 기준으로 작성했다. 예전 README의 정확도 백분율이나 연구용 이름만으로 사건 의미를 확정하지 않는다.

## 읽는 기준

- **구조 확인:** 레코드 경계·자료형·바이트 순서를 읽을 수 있다.
- **바이너리 의미 확인:** 특정 실행 파일의 수신 처리와 이름이 있는 소비 경로를 연결했다.
- **화면/정답 대조:** 실제 화면 또는 대응하는 캡처 시점의 정답과 비교했다. 적용한 경기·빌드 범위가 있다.

한 항목이 위 세 단계를 모두 통과했다는 뜻은 아니다. 특히 현재 수치, 그 수치의 증감, 실제 행동, 경기 종료 수치는 서로 다른 대상이다. 스냅샷 SET을 한 번의 처치나 골드 획득으로 세지 않는다.

## 시간·개체 공통 기준

레코드 시각은 `timestamp`이며 해당 레코드 앞부분에서 읽는다. 기록 시간과 게임 시계는 별개이고, `046f` 게임 시계 앵커를 이용한 기존 `GameTime/RecordTime` 조회를 유지한다. 보간값을 화면의 정확한 시계로 단정하지 않는다. 레코드의 프레임 번호·인덱스·오프셋·전체 payload를 보존한다.

플레이어, 터렛, 몬스터, 투사체, 장판 등의 개체 종류와 ID 수명은 따로 검증한다. 같은 정수 값이라는 이유로 팀 ID를 플레이어 참조로 취급하거나, 모든 참조를 가해자·피해자로 이름 붙이지 않는다. 좌표도 이 ID·시각 체계에 연결한다.

## 지금 실행할 수 있는 것

```bash
# native 의미를 확인한 필드와 원본 레코드를 JSONL로 추출
python -m vg.analysis.event_timeline replay.0.vgr -o events.jsonl

# 전역 종료 액션만 추출. --entity 필터는 전역 액션을 제외하므로 함께 쓰지 않는다.
python -m vg.analysis.event_timeline replay.0.vgr --opcode 0x03f1 -o end-actions.jsonl

# 특정 게임 시점의 KDA. 최종 경기 결과와 다른 scope를 사용한다.
python -m vg.decoder_v2.decode_match replay.0.vgr --at-game-time 1551 -o capture.json
```

`03f1`에는 `native_winning_team_raw`, `native_winning_team_id`, `native_end_reason`, `native_surrender`, 빌드 근거가 붙는다. 승리 팀 ID를 화면의 left/right로 변환하지 않으며 `match_completed`를 출력하지 않는다. 오류/무시 경로로 가는 종료 사유도 있기 때문이다. `048d`의 native 소비 경로는 이번에 문서화했고, 전체 구조의 제품 출력은 아직 구현하지 않았다.

## 이어갈 순서

1. 종료 액션·게임 후 통계와 실제 결과 화면 사이의 경계를 추가 검증한다. 같은 시각의 뒤쪽 레코드를 버리지 않는다.
2. 기본 카운터·경제·아이템을 검증한다. 기존 294/294는 캡처 시점 KDA의 근거로만 유지한다.
3. 목표물 종류·소유 팀을 확인하고 개별 처치와 팀 보상을 연결한다.
4. 전투·생명주기·좌표를 대조한 뒤 스킬·효과를 캐릭터별로 확장한다.

영상은 모든 구조 분석의 선행 조건이 아니다. 바이너리에서 의미를 좁힌 뒤 실제 행동과 시각을 검증하는 독립 자료로 사용한다.
