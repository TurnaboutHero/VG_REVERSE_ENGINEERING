# 좌우 팀 라벨 — 바이너리 채널은 닫혔다

2026-08-10. `unified_decoder.py` 머리말이 오래 "미해결"로 달아둔 문제를
끝까지 밀어본 기록. 결론은 **풀 수 없다**이고, 못 푸는 이유가 문제 자체의
성격에 있다.

## 라벨이 양쪽에서 무엇을 뜻하는가

먼저 두 라벨이 서로 다른 것을 가리킨다는 걸 확인했다.

**디코더 쪽.** `vgr_parser.py:156` 이 전부다.

```python
if team_id == 1: return "left"
if team_id == 2: return "right"
```

플레이어 블록 `+0xD5` 의 값을 그렇게 부르기로 한 것뿐이다. 유도가 아니라
작명이다.

**진실값 쪽.** `tournament_ocr.py:237` 이 결과 스크린샷을 `width * 0.5` 로
갈라 왼쪽 열을 `left` 로 적는다. 즉 **화면 배치**다.

둘은 애초에 같은 것을 재고 있지 않았다.

## 세 번의 측정

| 후보 채널 | 진실값 열과 일치 |
|---|---|
| `team_byte` 값 (1 → left) | **6 / 11** |
| 파일 내 첫 플레이어 블록의 팀 | **7 / 11** |
| 맵 x 좌표 순서 | **6 / 11** |

셋 다 동전던지기다.

### 좌표가 왜 정보량 0인가

이전 세션에서 "진영별 x 중앙값이 11/11 로 정렬된다"를 좌표의 성과로 적었다.
**그건 순환논증이었다.** 그때 쓴 팀 라벨이 `team_byte` 로 만든 것이라,
`team_byte` 로 나눈 두 집단을 `team_byte` 와 대조한 셈이다. 반드시 11/11 이
나온다.

실제로 성립하는 사실은 이것이다: **`team_byte` 1 이 항상 맵의 저-x 쪽이다
(11/11).** 그래서 x 순서와 `team_byte` 는 *같은 분할*이고, x 는 바이트가
모르는 것을 알 수 없다. 좌표는 이 문제에 대해 미검정이 아니라 **반증**이다.

`map_side_check.py` 가 이 구조를 그대로 보여준다. 경기별 일치 수가 10/10 아니면
0/10 이고 그 사이가 없다 — 분할은 언제나 완벽하고, 이름만 절반의 확률로
뒤집힌다.

### 블록 순서도 아니다

`team_byte` 시퀀스를 파일 순서대로 늘어놓으면 `1212221112`, `2121122121`
처럼 **뒤섞여 있다**. 팀별로 묶여 저장되지 않으므로 "로비 슬롯 순서" 라는
가설 자체가 성립하지 않는다.

## 진실값 라벨은 경기의 성질이 아니다

결정적인 관찰. 토너먼트 시리즈 안에서

- 화면 열은 **고정**이다 (m1·m2 둘 다 왼쪽이 2600 팀, m10·m11 둘 다 3000 팀)
- `team_byte` 는 **경기마다 뒤집힌다**

이건 팀이 경기마다 진영을 바꾸는 것과 정확히 같은 그림이다. 화면 열은
로스터 정체성을 따라가고, `team_byte` 는 맵 진영을 따라간다. 리플레이
바이너리는 경기를 기록하지 로스터 순서를 기록하지 않으므로, 화면 열은
바이너리에 있을 이유가 없다.

리플레이 파일명의 UUID 쌍도 이를 뒷받침한다. 앞 UUID 는 계정이고 뒤는 경기
ID 인데, 같은 계정 `d8736287` 이 서로 다른 시리즈 9경기에 걸쳐 나타나고,
`02aae104` 는 자신이 참가하지 않은 경기(m11, Buffalo vs RRONE)의 소유자다.
소유자는 참가자가 아니라 수집자이므로 "소유자 팀이 왼쪽" 도 성립하지 않는다.

## 남긴 것

`DecodedPlayer.map_side` (`"low_x"` / `"high_x"`). `team` 은 건드리지 않았다 —
`truth_comparison.py` 의 auto-swap, `objective_detector`, `kda_detector`,
`vgr_database`, 익스포터가 그 값을 읽고 있고, 의미를 바꾸면 정확도 이득 없이
호출부만 깨진다.

`map_side` 는 `team_byte` 를 복사하지 않고 **좌표에서 실측**한다. 둘이 11/11
로 맞지만, 복사해버리면 그 일치가 반증 불가능한 동어반복이 된다. 재면 앞으로
어긋나는 리플레이가 나왔을 때 드러난다.

`team` 과 달리 `map_side` 는 디코더 바깥과 비교해도 살아남는다. 화면의 열이
아니라 맵을 가리키기 때문이다.

## 회귀

없다. 좌표를 읽지 않으면(`detect_positions=False`, 기본값) `map_side` 는 빈
문자열이고 좌표는 0개다.

| | 값 |
|---|---|
| 게이트 재현율 | 202/204 = 99.0% |
| 게이트 정밀도 | 202/211 = 95.7% |
| 홀드아웃 칸 수 일치 | 49/60 |

## 곁가지 두 개

- 진실값 이름 매칭이 3경기에서 한 명씩 실패한다 (m5·m6 `2600_TenshiiHime`,
  m9 `1899_1CN`). OCR 표기 흔들림이고, 6/11 이나 7/11 을 법칙으로 바꿀 수 있는
  거리가 아니라 결론에는 영향이 없다.
- `gate_sales.py` 는 빌드 로직을 스크립트 안에서 다시 짜기 때문에 디코더가
  바뀌어도 숫자가 안 움직인다. 회귀 검사에는 `gate_prod.py` 처럼
  `UnifiedDecoder` 가 내놓는 `items` 를 직접 채점하는 쪽을 써야 한다.

## 더 안 볼 것

스크린샷의 출처(중계 오버레이, 캐스터 시점, VOD 를 누가 받았는지)는 가진
자료로 반증할 수 없다. 수렴하지 않는 실이므로 여기서 끊는다.
