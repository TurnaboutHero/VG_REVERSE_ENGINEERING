# 종료 액션과 최종 집계 경계 조사

2026-09-08 UTC / 9월 9일 한국 시간까지의 조사. [전체 이벤트 목록](EVENT_CATALOG_2026-09-08.md) 중 종료 기준을 먼저 확인했다.

## 이번에 확인하고 구현한 것

기존 종료 판정이 사용하지 않던 `0x03f1`을 Windows 바이너리의 `Nuo::Kindred::ActionEndMatch`까지 추적했다. 입력에는 승리 팀 값과 종료 사유가 있다. 결과 처리에서 팀 비교를 `win`으로, **사유가 2인지**를 `surrender`로 내보내는 경로까지 확인했다.

기존 `event_timeline`은 이제 이 레코드의 native 필드를 기본 출력에 포함한다. 원본 전체 32비트 값과 native 생성자가 사용하는 하위 8비트 팀 ID를 따로 보존한다. 팀 ID를 화면 좌우로 바꾸거나, 접수된 액션을 곧바로 `match_completed`로 승격하지 않는다. 사유 5/6/7은 검증 오류 처리, 8은 무시 경로로 가기 때문이다. 사유 0은 이 소비 경로에서 비항복으로 처리되지만, 모든 사유 0을 크리스탈 파괴로 부를 근거는 아직 없다.

또한 `completeness.py`의 일반 상태 전환·크리스탈 후보·아이템 후보가 다음 레코드의 시각이나 내장된 가짜 헤더를 읽을 수 있던 문제를 고쳤다. 기존 strict record parser의 **해당 레코드 시각**을 사용한다. 후보 ID 범위·시간 상한·완료 판정 임계값은 바꾸지 않았다.

## native 근거의 범위

대상 Windows PE32 실행 파일 SHA-256:

`659f9eed557a426db57554d2a768efe34ba9fe02ba1085d77db64390b0d92642`

- `03f1` → 생성자 `0x0081a680` → RTTI-backed ActionEndMatch vtable → 복사/큐 삽입 → apply → 게임 종료 상태 요청.
- 결과 경로 `0x00548c90` → `0x004c1370` → analytics `0x004c13b0`의 `win`과 `surrender` 키.
- 이 native reader가 소비하는 본문은 BE32 + 사유 byte, 총 5바이트다. 로컬 레코드는 content length 8, 즉 opcode 2바이트와 본문 6바이트다. 남은 1바이트를 타임라인에 보존한다.
- 시각은 액션 본문에 없다. `timestamp`는 기록 봉투의 시각이며 게임 시계와 다르다.

[상세 분석](evidence/2026-09-08-endgame/native-static-analysis.md), [VA/RVA](evidence/2026-09-08-endgame/addresses.md), [생성자·vtable 근거](evidence/2026-09-08-endgame/end-evidence.txt), [dispatcher 발췌](evidence/2026-09-08-endgame/dispatcher-excerpts.c), [소비 경로 발췌](evidence/2026-09-08-endgame/native-consumer-excerpts.txt)를 함께 보관했다. 다른 빌드의 모든 동작까지 입증한 것은 아니다.

## 경기 후 큰 통계 메시지

`0x048d`는 content length 1616인 메시지로 관찰됐다. 이 Windows reader는 그 본문의 1612바이트를 복사해 16개 플레이어 슬롯·두 팀의 통계 구조를 채운다. 확인한 소비 이름에는 다음이 있다.

- 영웅 피해량, WP/CP/True 피해량, 구조물 피해량
- 5분 시점 라인·정글 파밍 및 순자산
- 아이템 ID 배열
- 팀 구조물 처치, Blackclaw/Ghostwing 관련 통계

이는 **누적·요약 통계**의 근거다. 각각의 공격·구매·목표물 처치 시각을 담은 사건으로 해석하지 않는다. 해당 analytics의 K/D/A는 live actor 경로에서 읽으며, 시간도 기존 게임 시계 getter에서 읽는다. 따라서 `048d`를 직접적인 최종 KDA·종료 시간 패킷이라고 부르지 않는다. 전체 `048d` 파싱·제품 출력은 이번 변경에 포함하지 않았다.

## 원본 56개 기록의 종료 주변 분포

모든 파일을 strict framing으로 읽었다. 55개 기록에서 `048d`와 `03f1`이 하나씩 발견됐고, 나머지 하나는 이미 `mixed_segments`로 분류한 M9이다. 사유 0이 50개, 사유 2가 5개였다. 두 시작 시계 이상 기록의 `unsupported_clock` 상태도 그대로 둔다.

55개 모두 `03f1` 뒤의 레코드가 0~65개였고, 뒤쪽 레코드의 기록 시각은 종료 액션과 같았다. 이 분포는 이번 코퍼스 관찰이며 형식의 보편 규칙이 아니다. `048d`는 직접 통계 구조를 갱신하고 `03f1`은 액션 큐를 사용하므로, 파일의 바이트 순서를 화면 갱신 순서로 치환할 수 없다.

**현재 결론은 종료 액션의 바이트 위치에서 잘라 버리지 않고 같은 시각의 후속 갱신을 보존하는 것이다.** 자동 최종 집계 cutoff로 승격하려면 실제 적용·결과 표시 순서와 해당 시점의 통계를 더 확인해야 한다.

## 화면과 파일을 함께 확보한 항복 대조군

기존 PC 클라이언트에서 직접 만든 연습 경기다. 후킹·프로세스 메모리 읽기 없이 UI 입력과 게임 창 캡처만 사용했다.

- 게임 중 스코어보드에서 항복을 눌렀고, 화면은 붉은 `항복`과 `4:47`을 표시했다.
- 0.5초 목표 간격의 게임 창 이미지 229개, 약 114.5초 구간을 보관했다. 결과 화면의 시각이 `4:47`에 고정되는 것도 확인했다. 이는 영상 인코딩 파일이 아닌 타임스탬프가 붙은 연속 이미지다.
- 저장된 29개 리플레이 섹션을 해시로 보관했다. 마지막 기록 시각은 `289.887451`초, 마지막 섹션 앵커로 환산한 게임 시각은 `287.735992`초다. 후자의 정수 초가 화면 `4:47`과 맞는다. 환산값이 실제 표시 전환의 정밀 시각임을 입증한 것은 아니다.
- `048d`는 기록 시각 `289.869598`, `03f1`은 `289.887451`에 있다. `03f1` 본문 `000000020200`은 승리 팀 값 2·사유 2로 해석된다.
- native K/D/A와 화면은 모두 0/0/0이었다. 전투가 있는 경기의 최종 KDA 정확도 증거로 확대하지 않는다.

## 캡처 시점과 마지막 기록은 다르다

기존 11개 정답 경기 중 정상 시계를 가진 10개·이름이 정확히 대응하는 98명을 같은 방식으로 비교했다.

| 조회 기준 | K/D/A 일치 |
|---|---:|
| 기존 정답의 캡처 게임 시각 | 294/294, 이전 native integration 검증 |
| 이번에 마지막 기록까지 읽은 상태 | 288/294 |

불일치 6개는 M5와 M6에 각각 3개였다. 두 기록의 마지막 게임 시각 환산값은 정답에 적힌 시각보다 약 19.5초·22.4초 뒤다. 그러므로 이전 294/294를 최종 경기 수치의 증거로 다시 쓰지 않는다. 정확한 캡처 관계와 결과 표시 경계를 추가 확인해야 한다. M9의 비교 값은 계속 unavailable이다.

승리 팀 ID도 화면의 left/right와 같은 좌표계가 아니다. 예를 들어 M2/M3/M8/M10은 종료 액션의 팀 값이 2인데 제공된 정답의 승자는 left다. 타임라인은 원본 팀 ID만 제공하며 화면 좌우 변환을 추정하지 않는다.

- 실제 타임라인 CLI: `--help`, 녹화한 항복의 `--opcode 0x03f1` 추출, 잘린 입력의 종료 코드 2 확인.

## 추가 직접 경기와 복구

비항복 종료 대조를 위해 기존 115섹션 리플레이를 임시 슬롯에 넣어 실행했으나, 장면을 확인하기 전에 클라이언트가 종료됐다. 원인은 이번 조사에서 확정하지 않았다. 임시 슬롯의 원래 23섹션을 해시로 검증해 복구하고, 주입한 나머지 92섹션만 원본 해시 확인 후 제거했다. 원본 코퍼스는 수정하지 않았다.

이후 직접 연습 경기에서 레벨 12, 아이템 구매, 사망 뒤 부활을 화면으로 확인했다. 크리스탈 물리 파괴에는 도달하지 못했으며 마지막에 항복했다. 결과 화면은 `20:07`, K/D/A `0/1/0`, 레벨 `12`, 표시 골드 `33.9k`였다. 종료된 경기의 121섹션을 별도 해시 백업했다. native 상태도 K/D/A `0/1/0`으로 일치했고, 마지막 앵커의 게임 시각은 `1207.060181`초였다. [두 직접 경기의 구조화 대조](evidence/2026-09-08-endgame/runtime-controls.json)를 보관했다. 이 자료는 후속 경제·전투 사건 대조용이며, 미검증 골드 의미나 개별 구매 이벤트를 확정하지 않는다. 연속 게임 창 캡처는 10분 제한에서 종료됐으므로 이 경기 전체 영상은 아니다.

조작 설정을 원래 우클릭 방식으로 복구한 화면을 확인했다. 소유한 게임·UI worker를 종료하고 이번 조사에서 만든 예약 작업 5개를 제거했다. 다른 프로세스와 Steam은 유지했다.
